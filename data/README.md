# AoM datasets (`.jsonl`)

This prototype expects one JSON object per line.

You can (re)generate a non-trivial templated suite via:

```bash
python scripts/generate_data.py --out_dir data --seed 0
```

## Disambiguation (`disamb_pairs.jsonl`)

Each line is a `DisambPair`:

- `pair_id`: string
- `target`: substring to patch/track (e.g. `"bank"`)
- `target_occurrence`: 0-based occurrence of `target` in each prompt
- `a`: `{ "prompt": str, "expected_label": str }`
- `b`: `{ "prompt": str, "expected_label": str }`
- `choices`: `{ label: [continuation_str, ...], ... }`
- `metadata` (optional): generator/debug fields; recommended keys include:
  - `type`: e.g. `"lexical"`
  - `word`: ambiguous target word
  - `labels`: the label set used in `choices`
  - `source`: e.g. `"template"`
  - `variant`: e.g. `"easy"` or `"hardened"`
  - `pair_variant`: e.g. `"clean"`, `"distractor"`, `"paraphrase_clean"`, `"paraphrase_distractor"`

Continuation strings should typically include leading spaces (GPT-2 tokenization),
e.g. `" river"`, `" loan"`.

Tokenization hygiene:
- For each (prompt, continuation), either the prompt should end with whitespace or the continuation should begin with whitespace.
- The loaders validate this boundary by default to avoid silent tokenization artifacts.

## Counterfactual (`counterfactual.jsonl`)

Each line is a `CounterfactualPair`:

- `item_id`: string
- `base`: `{ "prompt": str, "expected_label": str }`
- `cf`: `{ "prompt": str, "expected_label": str }`
- `choices`: `{ label: [continuation_str, ...], ... }`
- `intervention_type`: string (e.g. `"negation"`, `"cue_swap"`)
- `contrast_labels` (optional): `[label0, label1]` specifying the two labels used for AoM-CF shift scoring
- `expected_effect` (optional): expected intervention impact on the contrast:
  - `"shift"`: meaning-relevant intervention; expected label flips between base and cf
  - `"invariant"`: meaning-preserving sham control (no flip)
  - `"graded"`: meaning-relevant partial intervention (no flip; expect intermediate shift magnitude)

Notes:
- For `"shift"` items, `contrast_labels` may be omitted; it will be inferred as `(base.expected_label, cf.expected_label)`.
- For `"invariant"` and `"graded"` items, `contrast_labels` is required to define the comparison label.

## Coherence (`coherence.jsonl`)

Each line is a `CoherenceItem`:

- `item_id`: string
- `context`: string (long context ending where the continuation starts)
- `valid_continuations`: list of strings
- `invalid_continuations`: list of strings
- `constraint_type`: string (e.g. `"entity_state"`, `"temporal_order"`)
- `group` (optional): string for controls (e.g. `"main"`, `"ablate_relevant"`, `"ablate_irrelevant"`)

When coherence controls are generated by `scripts/generate_data.py`, items come in matched triplets
that share a base scenario; `base_id` can be derived by stripping the suffix after `__` in `item_id`
(e.g., `"entity-state-3__main"` → base `"entity-state-3"`). The evaluator reports paired deltas
bootstrapped over `base_id`.

`scripts/generate_data.py` only emits these control triplets when `--coh_include_controls` is set.
